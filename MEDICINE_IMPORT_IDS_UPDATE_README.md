# Pharmacy-specific medicine import IDs

## Changes
- Added `PharmacyMedicineImportIdentity` entity and `DbSet` / model mapping.
- Added EF Core migration `20261016100000_AddPharmacyMedicineImportIdentities`, which creates a pharmacy-scoped ID mapping table and backfills existing medicine imports using `ROW_NUMBER() OVER (PARTITION BY PharmacyId ORDER BY Id)`.
- Validation creates the next public ImportId for the authenticated pharmacy, regardless of branch, protected by a SQL Server transaction-scoped application lock.
- Import endpoints (commit, status, errors, staged rows create/list/edit/delete) resolve public `(PharmacyId, ImportId)` to the original `MedicineImports.Id` and retain existing branch access checks.
- Existing CMS/internal foreign keys and `MedicineImports.Id` remain unchanged.

## Install
1. Back up your SQL Server database.
2. Replace the project files with this ZIP's contents.
3. In Visual Studio Package Manager Console run `Build` / rebuild solution, then `Update-Database` using the correct startup/default project.
4. Do not manually create the mapping table first; the migration creates and backfills it.
5. Test validation and commit with two different pharmacy accounts. Each pharmacy's first public import ID should be 1.

## Verify
```sql
SELECT pmi.PharmacyId, pmi.ImportId, pmi.ExistingImportId, mi.BranchId, mi.FileName
FROM dbo.PharmacyMedicineImportIdentities pmi
JOIN dbo.MedicineImports mi ON mi.Id = pmi.ExistingImportId
ORDER BY pmi.PharmacyId, pmi.ImportId;
```

## Notes
- Branch-specific catalog/stock behavior has NOT been changed.
- No .NET SDK was available in the artifact-generation environment; compile and run migrations in Visual Studio before deploying.
- The EF Core model snapshot has not been regenerated by `dotnet ef`; regenerate/check the snapshot when making the next model migration.
